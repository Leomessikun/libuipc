# Independent training and economics audit

> Historical audit of `dc953a34`. See the [final review and implementation status](2026-09-13-pretraining-infrastructure-review.md) for fixes and remaining limitations.

Audited baseline: dc953a34, 2026-09-13. Read-only audit first; subsequent authorized edits limited to the cost probe and its tests. No GPU experiment.

## Findings

1. **The published cost probe does not measure an actor update.** `rlt_cost_probe.py:92-100` calls `timed(update, 2)`. `timed` performs one warm-up update, then two timed updates, starting at update zero. `SACConfig.actor_update_freq=4`; updates 2 and 3 contain no actor or temperature optimizer work. Ratios from those measurements do not establish amortized SAC throughput. Measure complete least-common-multiple actor/target cadence cycles after separate warm-up cycles. CUDA synchronization and allocated-memory peaks must bracket the measured work.
2. **The displayed cloud count counts distinct frame slots, not spatial encoder forwards.** On the baseline, single-frame critic-only updates encode B clouds in actor, target critic, and online critic (3B total); every fourth update adds two B passes. RLT prefix updates encode B(H+1) in actor, twice that in target, and once in online critic (4B(H+1)); the actor step adds two more online-critic passes. Full-cadence means for 64 nominal learning positions are 224 single-frame clouds and 324 RLT-H8 clouds, not 64 and 72. Hook-based counting confirmed the schedules on a tiny CPU PointNet++ model: single B16 updates total [48,48,48,80], RLT B2/H8 total [72,72,72,108]. Distinct input positions remain useful as a separate metric.
3. **64 positions is nominal, not measured.** With four 64-step synthetic episodes and padded H8 endpoint-uniform sampling, expected valid positions per batch of 8 is 60.5, not 64. The probe divides by 64 regardless of padding. At real horizon 300 the expectation is 63.2533, so this effect is small after full replay but material near starts/short episodes. Aggregate `learning_positions` returned by the update.
4. **All-position prefix learning changes the replay distribution.** `replay.py:290-327` samples endpoints uniformly, then walks backward; `_update_rlt` learns every valid position. For an isolated N>=H episode, transition t is included min(H,N-t) times across the N possible endpoints. At N300/H8, interior positions appear 8 times, while final 7 positions appear 7,6,5,4,3,2,1 times. Mask-normalized random batches can introduce additional weighting from short windows. This is not uniform-transition SAC. It particularly reduces endpoint supervision. Sampling each transition as a uniform learning endpoint resolves this; a chunked algorithm needs a deliberate sampling/weighting contract.
5. **Training and collection have different histories.** Baseline all-position RLT learns context depths 1..H in each reset window. Collection ordinarily uses H observations. Its final Bellman successor can use H+1 frames, whereas the next collected action drops the oldest frame and uses H. Thus an H8 result mixes architecture, objective context, and sampling effects. The companion change implements finite-window endpoint semantics; legacy prefix mode should remain explicitly labelled rather than silently change checkpoints.
6. **Batch size and update budget need separate reporting.** `gradient_update_budget` (`sac.py:53-65`, called at `pretrain_wang.py:720`) budgets optimizer updates per newly collected transition. It does not divide by H. B8/H8 prefix versus B64/single matches roughly 64 nominal supervised positions per optimizer update, but not independent trajectories or gradient covariance. B64/H8 prefix would create an 8x loss-position/data-reuse change. Report optimizer updates/new transition, actual learning positions/new transition, sampled windows, actor steps, elapsed collection/update/evaluation time. For endpoint mode, use B64 when comparing the B64 single-frame baseline.
7. **Unnecessary actor autograd graph on non-actor steps.** `_update_rlt` builds actor-head and sampled-action graphs before checking the every-fourth actor schedule. Target uses those actions inside `no_grad`, so on the other three steps the actor graph is never differentiated but still occupies memory during critic backward. Conditional `no_grad` on non-actor updates is a valid optimization, provided actor cadence and gradients are tested.
8. **Pretraining is not action-conditioned dynamics.** `TrajectoryPretrainingHead` predicts next privileged state and reward only from s_t, before a_t. Random/failed behavior therefore averages effects of distinct actions; the result cannot be treated as a candidate-action predictor. The command MSE learns conditional behavior means (zero under independent uniform random exploration). A separate prediction head avoids directly fitting the SAC policy trunk, but does not remove this representational objective issue. Dynamics targets should condition on recorded a_t; behavior imitation needs explicit data-quality/task intent. The raw loss also sums coordinate errors without normalization or component weights (privileged state has many more dimensions than command/reward).

## Positive findings

- Recorded actions, not newly sampled actions, advance target-critic history. Candidate actions branch locally and retain dense spatial `dQ/da`.
- The target recurrent module receives Polyak updates with the target encoder; online critic history is rebuilt after its optimizer step before actor-Q evaluation.
- Episode-aware replay carries boundaries and true saved successor observations; padding is masked, and stream histories are reset on physical discontinuities.
- No evidence from this audit that force signals are required to repair these infrastructure issues. No success-rate claim is supported by CPU tests.

## Recommended experiment contract

Evaluate the corrected dense stateless baseline, exact finite-history endpoint frame/RLT arms with matched learning positions and cadence, and retain prefix RLT only as a clearly different objective. Log complete cycle cost and separate acting/simulation/evaluation time. A recurrent architecture can help partial observability, but these changes alone do not establish that insufficient history is the elbow bottleneck.
